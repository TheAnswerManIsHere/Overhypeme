Overhype.me's codebase is built by agents and will be built by swarms of
agents with David out of the loop. The direction is a codebase that is
**legible to an agent by construction**: structure an agent can query rather
than scan, invariants a machine enforces rather than prose describes, and

## Problem

Navigation cost in this repository is paid by every agent on every task:
finding the owner of a behaviour whose name does not match its file, reading
far more of a 4,063-line route file than a task needs, and performing the
class-level sweep the working agreements require by grep, which is the step
the record says I most often get wrong in my own favour. The existing map,
`architecture-map.md`, is hand-written, 485 lines, and opens by telling the
reader not to rely on it. The research (notes committed with this plan)
says what helps: a structural graph queried narrowly at forced moments,
structure enforced by machines, and a small resident load. A swarm of agents
working without David will pay this cost in parallel, and will collide on
the monoliths. The handbook now ships the tool; this repository has not
adopted it.

## Proposed Design

**The tool arrives by sync, unmodified.** It brings:
- `scripts/map.mjs` (`build`, `check`, `deps`, `dependents`, `route`,
  `routes`, `table`, `purpose`, `subsystem`, `unresolved`, `freeze`,
  `ratchet`) and `scripts/map-eval.mjs`;
- the contract and the eval protocol;
- `config.schema.json`;
- five configuration seeds under `.agents/map/`: `config.json`,
  `subsystems.json`, `architecture.json`, `size-baseline.json` and
  `eval-tasks.json`;

## Implementation Steps

- **Phase 0, the sync** (one PR). Deliver the handbook payload with
  `scripts/sync.mjs`. The dry run on 2026-10-14 showed 6 seeds created, 2
  existing seeds kept, and nothing deleted. No configuration is filled in.
- **Phase 1, configuration and the index** (one PR):
  - complete `config.json` (decisions 1 and 2) and `subsystems.json`
    (decision 8);
  - set the rule file's `paths:`;
  - run `build` until there is no coverage gap, then commit the index;
  - record the acceptance journeys.

  All four files stay `"adopted": false`.
- **Phase 1b, the header backfill** (one or more PRs, by subsystem). Add
  purpose lines and tags to every file in the headered set. The mechanical
  pass may go to Sonnet subagents in batches, with the subsystem inferred from
  the path and the owning `docs/ai-context` doc, and I review every batch
  before commit. The index is rebuilt in each PR.
- **Phase 2, the manifest, the baseline, adoption and CI** (one PR):
  - author `architecture.json` from intent (decision 9), with exemptions for
    the violations the index reveals;
  - run `freeze`;
  - set `"adopted": true` in all four files;
  - add `node scripts/map.mjs check` to the Build job;
  - review every remediation message.

  From this merge, the fleet rule binds here.
- **The eval**, after AI-Handbook #210 lands and a re-sync delivers it:
  1. record both arm commits on #683;
  2. write the thirty tasks in the pre-edit or class-sweep framing
     (decision 15);
  3. run `keys` at both commits, replace any task whose keys differ, and
     verify the resulting set by hand;
  4. run both arms, each agent rooted in its prepared run repository, keeping
     transcripts and recording query use;
  5. score, and set `enabled` from the verdict.

**Sequencing:** 0 → 1 → 1b → 2 → eval. A Phase 2 violation whose fix changes
behaviour is filed as a follow-up and exempted, never fixed in Phase 2.

## Risks and Mitigations

- **A wrong purpose line is worse than none.** Mitigation: the batch review;
  the tag is checked against a vocabulary; the sentence is reviewed, not
  guessed by the guard. Residual risk accepted: the guard cannot judge
  prose.
- **The index lies by omission.** Mitigation: the tool's three-section answers
  and its supported-form matrix. A form this tree uses that the matrix lacks
  is a handbook PR, never a local patch. #210 closes the two known recogniser
  gaps, neither of which this tree hits today.
- **Agents do not run the query.** The research measured 58% non-use of an
  offered tool. Mitigation: the fleet rule, the seeded path rule, and the eval
  that measures whether either works. Phase 3's mechanical gate comes later.
- **Freshness friction.** Every import change needs a rebuild before commit.
  Mitigation: `build` took about 60s on this tree, the refusal carries the
  command, and from Phase 2 a stale index cannot merge.
- **The index goes stale between Phase 1 and Phase 2**, because CI does not
  run `check` yet. Mitigation: queries refuse a stale index locally, and
  each Phase 1b PR rebuilds it.
- **The manifest blesses the mess.** Mitigation: decision 9 authors from
  intent and names every exemption; the exemption list is itself a
  measurement for the decomposition increment.
- **Build job time.** Mitigation: measured in Phase 2 and reported.
