# api-zod barrel (`lib/api-zod/src/index.ts`) is codegen output, not hand-edited

`lib/api-zod/src/index.ts` is **rewritten from scratch** by `lib/api-spec/patch-generated.mjs`
(the `apiZodIndexLines` array). That patch runs during `@workspace/api-spec run codegen`,
which is the `pretest` hook of `@workspace/api-server` (`codegen && tsc -p lib/api-zod`).

**Rule:** to add/keep a module export in the api-zod barrel, add the
`export * from "./<module>";` line to the `apiZodIndexLines` array in
`patch-generated.mjs`. Editing `src/index.ts` directly looks fine (and even commits
fine), but the next codegen/test run wipes it.

**Why:** a committed `src/index.ts` can be correct yet still break on the first
`pnpm --filter @workspace/api-server run test`, because pretest regenerates the file
from the patch array. A missing line there manifests at runtime as
`SyntaxError: ... does not provide an export named '<X>'` (ESM `export *` from a
module that is no longer re-exported), cascading failures across whole test shards.

**How to apply:** when a new api-zod source module (e.g. `taxonomyHealth.ts`) needs to
be consumable as `@workspace/api-zod`, edit the array in `patch-generated.mjs`, then
rebuild declarations (`pnpm tsc -p lib/api-zod/tsconfig.json`) so the composite `dist/*.d.ts`
matches.

## Composite project: dist vs src skew
api-zod is `composite: true` + `emitDeclarationOnly` → consumers **typecheck** against
`lib/api-zod/dist/*.d.ts` (via project references) but **run** against `src/` (tsx resolves
package.json `exports` → `./src/index.ts`). So tsc can pass while runtime fails (or vice
versa) if dist is stale. After changing api-zod source, rebuild dist (`tsc -p` or `tsc -b
--force`) to keep them in sync; deleting `*.tsbuildinfo` forces a clean rebuild.
